# مشاهدة الإعلانات — سياسة المنتج والتنفيذ الموحد

**الحالة:** قرار منتج معتمد من المالك بتاريخ 2026-11-22؛ مواصفة تنفيذ ملزمة. لا يفعّل هذا المستند مكافآت إنتاجية ولا يحدد أسعاراً إنتاجية ولا يثبت اكتمال التنفيذ البرمجي.

## 1. التسمية والتنقل
- الاسم الظاهر على الشاشة الرئيسية للعضو هو **مشاهدة الإعلانات**.
- يظهر بجواره قسم مستقل باسم **Media Workspace**.
- الدخول إلى «مشاهدة الإعلانات» يفتح قسمين: **الإعلانات التجارية العادية** و**الإعلانات التجارية المميزة**.
- لا تخلط الإعلانات العادية والمميزة في واجهة التصفح أو المشغل أو سياسة الاستحقاق.

## 2. الإعلانات التجارية العادية
### التصفح الجغرافي
- يبدأ التصفح بمخطط جغرافي مبني على البلدان والمناطق المفعّلة في التصنيف الجغرافي المعتمد.
- يختار العضو بلداً أو منطقة، ثم تظهر المواد المؤهلة ضمن النطاق.
- تعرض الإعلانات كبطاقات كبيرة وواضحة بصورة العرض واسم/عنوان يحدده المالك.
- العدد المستهدف لكل صفحة قابل للضبط ضمن تخطيطات 8 أو 12 أو 16 بطاقة، مع استجابة لحجم الشاشة وإمكانية الوصول.
- لا تظهر الحملة إلا بعد اجتياز موافقة النشر والدفع وفحص المادة والجدولة والاستهداف الخادمي.

### المشغل العادي
- اختيار بطاقة يفتح **مشغل الإعلانات التجارية العادية** المستقل.
- التوزيع المستهدف نحو 60% للمشغل و40% للمعلومات وعناصر التحكم والتنقل، بصورة متكيفة مع الهاتف واللوحي والاتجاه الأفقي.
- لا تمنح مكافأة عند فتح البطاقة أو المعاينة أو بدء التشغيل محلياً.
- لا تصبح المشاهدة مؤهلة إلا بعد إكمال دورة جلسة خادمية والتحقق من شروط السياسة والمدة والأدلة والميزانية.
- لا يستطيع العميل تعديل المكافأة أو العداد، ولا يعتبر المؤقت المحلي دليلاً على الاستحقاق.

### تكرار المشاهدة
- يجوز تكرار مشاهدة الإعلان العادي على فترات، وتستحق كل مشاهدة مؤهلة مكافأة مستقلة.
- يحدد Super Owner الحد اليومي/الفترة وعدد مرات الاستحقاق لكل إعلان من إعدادات خادمية ذات إصدار.
- لا تضع قيمة تجريبية أو حداً إنتاجياً ثابتاً في الكود. يجب أن تكون حدود التكرار قابلة للضبط من لوحة المالك، مع تحقق ذري خادمي.
- تغيير الحد أو المكافأة ينشئ إصدار سياسة جديداً؛ وتحفظ الجلسات snapshot لإصدار السياسة الذي بدأت عليه.

## 3. الإعلانات التجارية المميزة
### التصفح والاختيار
- لا يوجد مخطط جغرافي في واجهة الإعلانات المميزة.
- تعرض كبطاقات/أيقونات واضحة تحمل صورة تمييز واسم المعلن أو عنوان الإعلان الذي يحدده المالك.
- مصدر الأهلية والترتيب استعلام خادمي معتمد يدعم الأولوية والتنوع والجدولة والسحب الفوري.
- لا يستخدم الترتيب رسائل العضو الخاصة أو سماته الحساسة.

### المشغل المميز
- اختيار بطاقة يفتح **مشغل الإعلانات التجارية المميزة**، المستقل عن مشغل الإعلانات العادية وعن تدفق timed-ad القائم.
- مساحة المشغل المستهدفة نحو 60%، وتبقى 40% للمعلومات والخيارات والتنقل، مع تخطيط متكيف وإتاحة الوصول.
- لكل إعلان دورة جلسة خادمية: اكتشاف مؤهل، بدء، نبضات متسلسلة موثقة، إكمال أو إلغاء أو انتهاء، ثم مطالبة مكافأة ذرية عند استيفاء الشروط.
- لا تمنح مكافأة للمعاينة أو التشغيل المحلي أو النبضات المعادة/القديمة أو الإكمال المبكر.

### الاختصار العائم
- يوجد اختصار عائم للإعلانات المميزة عبر واجهات المنصة المسموح بها، ويستثنى منه سياق المحادثة الثنائية الخاصة والواجهات المستثناة سابقاً بقرار معتمد.
- يفتح الاختصار مباشرة تجربة الإعلانات المميزة ويبدأ العرض/التشغيل المتتابع وفق قائمة خادمية مرتبة بالأولوية والتنوع؛ مع احترام موافقة المستخدم على تشغيل الوسائط وإعدادات الصوت والبيانات.
- يبقى اختيار إعلان محدد متاحاً من داخل القسم.
- يحترم الاختصار الإيقاف والسحب وأهلية الحملة، ولا يظهر في سياق مستثنى.

### حد التكرار
- الحد الأقصى الثابت للإعلان المميز هو **10 مشاهدات مؤهلة لكل عضو لكل إعلان في اليوم**.
- يمكن للمالك تعيين حد أقل، ولا يجوز لأي إعداد أو واجهة أو API تجاوز سقف العشر مشاهدات اليومية.
- كل مطالبة تخضع أيضاً للميزانية والسياسة والاستحقاق الخادمي.

## 4. فصل النظامين
- المشغل العادي والمشغل المميز منفصلان في واجهات المستخدم وحالة التشغيل والتحليلات وسياسات الجلسات.
- لا تخلط مجموعات الحملات أو سجلات المشاهدة أو حدود التكرار أو المكافآت بين النظامين.
- يجوز استخدام محرك المحفظة والدفتر المالي المركزي الموحد؛ لا تنشأ محفظة أو ledger أو اقتصاد موازٍ.
- كل عمليات البدء والنبضات والإكمال والإلغاء والانتهاء ومنح المكافأة خادمية وذرية وقابلة للتدقيق ومحمية من إعادة الطلب والتزامن.

## 5. سيادة Super Owner على الاقتصاد وكل إعدادات المنصة
قرار المالك السيادي يشمل **كل اقتصاد Mawdda وكل المجالات الحالية والمستقبلية**، وليس الإعلانات فقط، بما فيها BetaCoins والمحفظة والمتاجر والاشتراكات والاستحقاقات والمنح والإعلانات وMedia Workspace وأسعار الخدمات ومددها وحصصها وأنواعها ومكافآتها وميزانياتها وسياسات نشرها وإيقافها واستردادها.

يجب أن تتيح بنية الإدارة للمالك، بحسب المجال:
- إنشاء وتعديل وتفعيل وتعطيل وأرشفة واستعادة المنتجات والخدمات والحملات والأنواع.
- تحديد السعر والعملة والمكافأة والعمولة والمدة والكمية والحصص وحدود الاستخدام والتكرار والميزانية وشروط الأهلية.
- تحديد جداول العرض والمناطق والأولوية والتنوع ومواعيد البدء والانتهاء.
- الموافقة والرفض والنشر والإيقاف والسحب والإلغاء والاسترداد والتسوية والمنح وسحب المنح.
- تعيين المشرفين وتفويض صلاحيات محددة وسحبها، مع بقاء قرارات المالك أعلى من التفويض.
- الاطلاع على التقارير والسجلات والتدقيق والتصدير وفق السياسة.

ضوابط التنفيذ:
1. المالك وحده يملك سلطة تغيير القيم الاقتصادية والسياسات السيادية؛ لا تمنح لمشرف أو مندوب افتراضياً.
2. كل تغيير يمر عبر API خادمي بصلاحية مالك مؤكدة وstep-up/MFA حيث يفرض عقد الأمان، مع versioning وسجل actor/time/reason/old/new values.
3. كل جلسة/شراء/مطالبة تحفظ snapshot لإصدار السياسة الذي بدأت عليه؛ لا تغيير صامت بأثر رجعي.
4. تبقى ضمانات صحة البيانات وعدم الصرف المكرر وعدم تجاوز الميزانية وصحة الدفتر والحماية من التلاعب فعالة؛ السيادة لا تعني تجاوز الأمان.
5. القيم التجريبية مسموحة حصراً في بيئة الاختبار/Emulator وببيانات اصطناعية وفصل واضح. لا تنقل تلقائياً للإنتاج.
6. لا تفعّل مكافآت أو تحصيلات أو أسعار إنتاجية افتراضية عند غياب إعداد مالك صريح؛ fail closed.

## 6. نموذج البيانات والخدمات
- حافظ على نموذج الحملات والإعلانات والتمويل القائم في E522 ولا تنشئ اقتصاداً موازياً.
- افصل نوع inventory (standard وfeatured) ومخطط التصفح ومشغل العميل وسياسة التكرار، مع عقود API واضحة.
- استخدم معرّف جلسة فريداً، نسخة حملة وسياسة ثابتة، حجز ميزانية، nonce/sequence للنبضات، ومفتاح مطالبة idempotent مشتقاً من الجلسة.
- إكمال الجلسة يعيد قراءة الحملة والسياسة والميزانية وحدود العضو والمحفظة داخل معاملة واحدة، ثم يقفل الجلسة ويستهلك الحجز ويكتب قيداً مالياً واحداً فقط.
- امنع العميل من الكتابة المباشرة إلى الحملات والجلسات والنبضات والمطالبات والعدادات والمحفظة والدفتر.
- لا تعتمد على foreground/visibility وحدهما كإثبات قاطع لهوية إنسان؛ هما إشارتان دفاعيتان إلى جانب التوقيت الخادمي ومكافحة الاحتيال.

## 7. الترحيل والاختبارات
1. جرد كود E522 والفرع المتخصص ومقارنة كل ملف وعقد API ومجموعة Firestore وفهرس وقاعدة أمنية قبل النقل.
2. استيعاب الوظائف الفريدة انتقائياً في E522؛ لا تستبدل نموذج التمويل أو المحفظة المركزية.
3. اختبر كل مجموعة دمج على الرأس المتراكم عبر GitHub Actions فقط وفق نطاق الاختبارات الداخلية المعتمد.
4. غطِّ: العرض الجغرافي للعادي، عدم وجود جغرافيا للمميز، الأولوية والتنوع، استثناءات الاختصار العائم، فصل المشغلين، الحدود اليومية، تكرار المشاهدة، إصدارات السياسة، السحب أثناء الجلسة، النبضات المعادة، التزامن، الميزانية المستنفدة، الدفع/الاسترداد، exactly-once، الصلاحيات، الأرشيف والتقارير.
5. لا تعتبر التوثيق أو وجود callable أو اختبار وحدة منفرد إثباتاً لاكتمال دورة المستخدم.
6. لا دمج إلى main أو نشر أو تعديل موارد Firebase الإنتاجية أو تفعيل فوترة أو موارد مدفوعة ضمن هذه المهمة.

## 8. معايير القبول
- الاسمان الظاهران مطابقان حرفياً: «مشاهدة الإعلانات»، «Media Workspace».
- داخل مشاهدة الإعلانات قسمان بالاسمين المعتمدين.
- التصفح الجغرافي متاح للعادي فقط.
- الاختصار العائم للمميز يظهر فقط في الواجهات المسموح بها.
- مشغلان مستقلان بتوزيع تقريبي 60/40.
- الحد المميز لا يتجاوز 10 مرات يومياً لكل إعلان/عضو؛ الحد العادي مضبوط من المالك خادمياً.
- مكافأة كل مشاهدة مؤهلة فقط، مع قيد مركزي ذري واحد.
- جميع القيم الاقتصادية قابلة لإدارة Super Owner بإصدارات وسجل تدقيق، ولا توجد قيم إنتاجية مخترعة.
- نجاح GitHub Actions على الرأس النهائي بعد الدمج، مع توثيق SHA والوظائف الناجحة والفاشلة.
