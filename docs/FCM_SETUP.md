# إعداد إشعارات مودة الفورية

## ما تم تنفيذه

- يسجل التطبيق رمز FCM الخاص بالعضو عبر callable موثوق، ويحفظه تحت حسابه فقط مع بصمة SHA-256 لمعرف المستند.
- يمكن إلغاء تسجيل الرمز عند تسجيل الخروج، وتُعطّل الرموز التي يعلن FCM أنها غير صالحة.
- يرسل الخادم إشعارات عامة لا تكشف نص الرسالة أو محتوى الغرفة إلى الإشعارات المباشرة والغرف.
- يعرض التطبيق إشعاراً موجزاً أثناء فتح التطبيق، ويستخدم Service Worker لإشعارات الويب في الخلفية.
- فشل FCM لا يلغي الرسالة أو سجل الإشعار المحفوظ.

## شرط تفعيل Web Push

1. من Firebase Console للمشروع التجريبي، افتح Project settings ثم Cloud Messaging ثم Web Push certificates.
2. أنشئ أو انسخ مفتاح Web Push public key (VAPID).
3. أضف المفتاح في GitHub Repository Variables بالاسم `MAWDA_FCM_VAPID_KEY`.
4. أعد بناء تطبيق الويب عبر GitHub Actions. لا تضع المفتاح الخاص أو بيانات خدمة في ملفات المستودع.
5. اختبر السماح بالإشعارات في متصفح يدعم FCM، ثم أرسل رسالة اختبار بين حسابين تجريبيين.

إذا لم يُضبط المتغير، يتعمد التطبيق تعطيل تسجيل Web Push بدلاً من طلب رمز غير صالح. لا يعني نجاح CI أو اختبار Emulator أن إشعاراً حقيقياً وصل إلى جهاز.

## حدود التحقق الحالي

- CI يختبر تسجيل رمز FCM وإلغاء تفعيله على Firestore Emulator.
- CI لا يثبت تسليم FCM عبر الإنترنت أو عمل إشعارات المتصفح/الهاتف فعلياً.
- يلزم إعداد Web VAPID، وتطبيق تجريبي مسجل في Firebase، ومنح صلاحية الإشعارات على جهاز/متصفح فعلي.
- لم تُضف إعدادات Android/iOS الأصلية إلى هذا المستودع؛ التحقق الفعلي الحالي يقتصر على Web بعد استكمال إعداد Firebase.
