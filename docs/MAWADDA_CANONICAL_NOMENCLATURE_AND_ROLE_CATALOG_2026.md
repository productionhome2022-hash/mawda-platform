# سجل المسميات القياسية والهوية الإدارية والعملة — Mawdda 2026

**المعرف:** NOM-001  
**التاريخ:** 2026-11-21  
**المستودع:** productionhome2022-hash/mawda-platform  
**الفرع:** codex/mawda-full-platform-implementation  
**الحالة:** توجيه مالك موثق؛ توحيد الوثائق المركزية منفذ على الفرع؛ المسح البرمجي الشامل والتطبيقات لم يكتمل بعد.

## 1. المالك الأعلى

- المسمى الظاهر والقياسي الوحيد للمالك: **Super Owner**.
- هوية مالك واحدة canonical UID؛ لا تنشأ هوية أو حساب مالك منفصل بسبب استعمال Owner أو Super Admin أو Super Owner في مصدر قديم.
- في واجهات المستخدم ولوحات الإدارة والوثائق الجديدة والترجمات والإشعارات ورسائل النظام، يستعمل Super Owner.
- قد تبقى claims أو enum أو collection fields أو identifiers legacy مثل `super_admin` لأسباب توافق، لكنها لا تظهر كاسم دور للمستخدم، ولا يعاد تسميتها قبل فحص المصادقة وقواعد Firestore/Storage وCloud Functions وAPI والبيانات والاختبارات.

## 2. الإدارة العامة

- التسمية القياسية: **Admin 1، Admin 2، …، Admin N**.
- العدد الفعلي متغير ويحدده Super Owner ويعدله؛ لا يوجد افتراض بعدد ثابت.
- لكل مقعد رقم/معرف ثابت لا يعاد استخدامه، وحالة مستقلة، ومجموعة صلاحيات يختارها المالك صراحة.
- لا يعني الترقيم ترتيباً في السلطة أو تطابق الصلاحيات. ولا يحق لأي Admin إنشاء Admin آخر أو توسيع صلاحياته إلا بتفويض صريح مستقل من Super Owner.
- لا تستخدم Admin N وحدها كاسم ظاهر لحساب؛ هي صيغة عامة للتسلسل.

## 3. عائلات إدارية متخصصة مستقلة

- **Admin Media 1–5:** إدارة الإعلانات وMedia Workspace؛ بحد أقصى خمسة وفق المواصفة المصدرية، مستقلة عن الإدارة العامة.
- **مشرف إنتاج عام 1–5:** خمسة مقاعد مستقلة وفق الدستور الحالي.
- **مشرف إنتاج الفريق:** صلاحيات محصورة بفريقه وغرفته ومهامه.
- **المشرفون القانونيون/الإداريون للعقود:** أربعة مقاعد تخصصية وفق الدستور وسجل العقود؛ لا توقيع دون تفويض توقيع مستقل وساري.
- **مندوب إعلانات معتمد:** دور تجاري تشغيلي منفصل، لا يكتسب صلاحيات الإدارة أو المالك.
- **فريق المراجعة التقنية للإنتاج:** نطاق مراجعة محدد ولا يكتسب صلاحيات عامة.

لا يجوز دمج هذه العائلات أو نقل صلاحيات بينها لمجرد تشابه كلمة Admin أو Supervisor. أي تعديل لأعداد المقاعد المتخصصة يحتاج الرجوع إلى مصدر القرار الخاص بها؛ مرونة عدد Admin 1…N لا تغير أعداد الأدوار الأخرى.

## 4. العملة

- الاسم العربي القياسي: **بيتاكوينز**.
- الاسم الإنجليزي القياسي: **BetaCoins**.
- يطبق الاسم على النصوص الظاهرة والوثائق التشغيلية الجديدة والترجمات والرسائل والإشعارات والمتجر والمحفظة والجوائز والمنح.
- يمنع استعمال «كوينز» أو «Coins» كاسم منتج بديل في واجهة Mawdda؛ وقد تظل كلمة coin في سياق تقني عام أو تاريخي لا يصف اسم العملة.
- لا تغيير تلقائي لأسماء حقول Firestore أو مفاتيح الدفتر أو API أو migration IDs أو السجلات التاريخية. أي تغيير داخلي يتطلب تحليل توافق وترحيلاً قابلاً للعكس واختبارات وقراءة رجعية.

## 5. قواعد التوحيد والتحقق

1. المسح مطلوب في Flutter Android/iOS/PWA/Web، Cloud Functions، قواعد Firestore وStorage، الترجمات، الإشعارات، رسائل النظام، الاختبارات، الوثائق، CI وواجهات API.
2. صنف كل تطابق إلى: مسمى واجهة، ترجمة، اسم دور تقني، claim، enum، سجل تاريخي، نص اختبار، أو اسم متغير/حقل.
3. صحح المسميات الظاهرة أولاً مع الحفاظ على الهوية والصلاحيات.
4. لا تستبدل النصوص آلياً داخل identifiers أو migrations أو بيانات الأعضاء.
5. اختبر أن Super Owner وحده يملك claim المالك، وأن Admin 1…N لا يتجاوز الصلاحيات المفوضة، وأن Admin Media والأدوار المتخصصة لا تتسرب صلاحياتها.
6. اربط كل تغيير بمعرف NOM-001 ومسار الملف وSHA ونتيجة الاختبار.
7. لا يعتبر توثيق هذه القاعدة دليلاً على اكتمال المسح البرمجي أو قبول التطبيقات.
