## 1. الغرض والنطاق

ينشئ هذا القسم مرجعاً موحداً للهوية البصرية، ونظام التصميم، وخريطة الشاشات وواجهات العرض، والأزرار والعناصر التفاعلية، والتنقل والصلاحيات، والخدمات والأعمال البرمجية المرتبطة بها في منصة Mawdda.

لا يقتصر النطاق على صور أو شاشات منفردة. المطلوب بناء خريطة تشغيلية وبصرية كاملة تغطي تجربة العضو والضيف والإدارة والإشراف وSuper Owner، وتربط كل عنصر مرئي بالوظيفة والخدمة والبيانات والصلاحيات والاختبارات والوثائق ذات الصلة.

يسري التخطيط على الموقع والويب المتجاوب وPWA وAndroid APK وiOS/iPadOS وتطبيقات سطح المكتب المستقلة، مع الحفاظ على تجربة وهوية موحدتين وتكييف العرض والتفاعل وفق المنصة والجهاز.

## 2. القرار المعتمد ومبادئه الملزمة

1. بناء خريطة شاملة لجميع الشاشات والواجهات والخلفيات والأقسام والأزرار وحالات الاستخدام، لا مجموعة نماذج تجميلية منفصلة.
2. اعتماد نظام بصري موحد لمنصة Mawdda، مع اختلافات تكيفية مدروسة بحسب حجم الشاشة ونظام التشغيل وطريقة الإدخال والدور والصلاحية.
3. تغطية واجهات المستخدم الشخصية والضيف، والإدارة العامة، وAdmin Media، وأدوار الإنتاج والإشراف، والواجهات السيادية الخاصة بـSuper Owner، دون خلط الصلاحيات أو إظهار عناصر غير مصرح بها.
4. ربط كل عنصر تفاعلي بوظيفته الفعلية ومساره ووجهته وخدماته الخلفية وبياناته وضوابطه واختباراته.
5. فحص الأعمال والملفات والخدمات الموجودة في فرع التطوير قبل أي إعادة بناء أو استبدال. التصميم الجديد لا يبرر إسقاط أعمال سابقة.
6. الحفاظ على الوظائف والخدمات والنماذج والعقود البرمجية القائمة متى كانت صحيحة؛ وتوثيق الفجوات والتكرار والتعارض قبل اقتراح التعديل.
7. لا يعني اعتماد الاتجاه البصري أن كل شاشة أو وظيفة منفذة أو مختبرة أو جاهزة للإطلاق.
8. لا تعديل على نص الدستور أو الرؤية المحميين لمجرد إضافة هذا القسم؛ تضاف الإحالات في مركز التوثيق وسجل القرارات، وأي تعديل على المرجعين السياديين يتطلب أمراً شخصياً صريحاً من المالك.
9. لا يجيز هذا القرار الدمج إلى main أو النشر أو تعديل الإنتاج أو Firebase الإنتاجي أو الفوترة أو الموارد المدفوعة.

## 3. المنصات وقنوات التثبيت والتشغيل

يجب التمييز بوضوح بين قنوات الوصول التالية وعدم اختزالها في تطبيق واحد:

| القناة | المقصود | متطلبات العرض والتوثيق |
|---|---|---|
| الموقع والويب المتجاوب | استخدام Mawdda من متصفح الهاتف أو الجهاز اللوحي أو الحاسوب | واجهات متجاوبة، تنقل مناسب للمتصفح، دعم RTL/LTR وإمكانية الوصول |
| تثبيت الموقع كتطبيق PWA | تثبيت نسخة الموقع نفسها من المتصفح كتطبيق ويب تقدمي عندما يدعم المتصفح والنظام ذلك | مدخل واضح في القائمة العلوية/القائمة المنسدلة باسم مفهوم مثل «تثبيت Mawdda على الجهاز»؛ يظهر ويتصرف وفق قابلية التثبيت الفعلية؛ يوثق Manifest وService Worker وأيقونات التطبيق وسلوك التثبيت والتشغيل والتحديث والعمل دون اتصال المسموح |
| Android APK | حزمة تطبيق Android مستقلة قابلة للتثبيت | واجهات Android التكيفية، دورة بناء وتوقيع وتوزيع مستقلة، وعدم اعتبار Debug دليلاً على Release |
| تطبيق سطح المكتب المستقل | تطبيق أصلي/مغلف مستقل لأنظمة Windows وLinux، وأي أنظمة سطح مكتب أخرى يعتمدها المالك بعد التحقق | حزم تثبيت مستقلة، دعم لوحة المفاتيح والفأرة والنوافذ وتغيير الحجم والاختصارات والملفات والإشعارات وفق ما تدعمه المنصة |
| iOS/iPadOS | تطبيق Apple مستقل | مراعاة أنظمة Apple وإعداداتها وهويتها الحالية؛ لا تغيير تسجيل iOS أو Bundle ID أو Firebase App Identity المحمية دون موافقة مستقلة |

**قاعدة PWA الإلزامية:** خيار تثبيت الموقع من القائمة العلوية جزء من تجربة الموقع ويجب أن يكون فعالاً وفق شروط الدعم الفعلية للمتصفح. لا يعرض كزر زائف أو يوحي بإمكان التثبيت عندما لا تسمح البيئة بذلك؛ تقدم عندها رسالة توضيحية أو تعليمات مناسبة. وهذا المسار مستقل عن تطبيق سطح المكتب ذي حزم Windows/Linux.

**حدود التوافق:** لا يعلن دعم نظام أو متصفح أو ميزة أصلية قبل فحص توافق الاعتماديات والإضافات والبناء والاختبار على البيئة المستهدفة.

## 4. نطاق الشاشات والأدوار

هذه خريطة نطاق تأسيسية قابلة للتوسعة؛ ليست حكماً بأن كل شاشة موجودة أو مكتملة في المصدر.

### 4.1 تجربة الزائر والعضو

- صفحات التعريف والترحيب والهبوط، التسجيل وتسجيل الدخول والتحقق واستعادة الحساب.
- الشاشة الرئيسية والتنقل العام والبحث والاكتشاف والأعضاء والاقتراحات.
- الملف الشخصي العام والخاص، تعديل الملف، المنشورات والقصص والألبومات والوسائط.
- المحادثات الخاصة والعامة وصندوق الرسائل والإشعارات والحظر والإبلاغ والاستئناف.
- الغرف العامة والخاصة والمستأجرة، تفاصيل الغرفة والحجز والإيجار والدفع والإلغاء والاسترداد والفعاليات.
- المكالمات والصوت والتسجيلات الحية والملفات الصوتية المرفقة، مع تمييز وظائفها وحدودها.
- الإعلانات ومشاهدة الإعلانات والإعلانات المميزة وسجل المكافآت.
- المتجر والمحفظة وبيتاكوينز والتحويلات والمنتجات والاشتراكات والاستحقاقات والهدايا.
- Media Saver، الإعدادات والخصوصية والأمان والجلسات واللغة والمظهر وإمكانية الوصول.
- حالات الحساب والعضوية والضيف والاستحقاق المنتهي والقيود والتنبيهات.

### 4.2 الإدارة والإشراف والإنتاج

- لوحات الإدارة العامة بحسب التفويض الفعلي.
- Admin Media وإدارة الإعلانات والمواد ومساحات العمل.
- مشرف الإنتاج العام ومشرف إنتاج الفريق ضمن نطاقهما المحدد.
- إدارة البلاغات والمراجعة والاستئناف والمحتوى والوسائط والغرف والفعاليات.
- مركز العقود والطلبات والتكليفات والتوقيع وسجل التدقيق بحسب الدور.
- لوحات المراقبة والتقارير والتشغيل، دون منح صلاحيات ضمنية.

### 4.3 Super Owner

- لوحة المالك ومركز العمليات الموحد.
- إدارة الأعضاء والأدوار والتفويضات والجلسات والسلامة.
- الاقتصاد والمحافظ وبيتاكوينز والأسعار والحصص والمتجر والاستحقاقات والمنح.
- الإعلانات ومشاهدة الإعلانات وMedia Workspace والإنتاج والعقود.
- الوسائط والاحتفاظ والسياسات والخصوصية والإعدادات.
- المنصات والإصدارات والتكلفة والسحابة والنسخ والاستعادة والتدقيق.
- التحكم في الميزات والواجهات والأزرار وإعدادات العرض وفق الضوابط القانونية والتقنية وسجل التدقيق.

تظل المسميات وحدود الأدوار وفق سجل المصطلحات والقرارات المعتمدة؛ لا تنشأ أدوار أو صلاحيات جديدة من التصميم.

## 5. نظام الهوية البصرية والتصميم

تُبنى المواصفات التفصيلية على وثيقة الهوية وتجربة المنتج القائمة `MAWADDA_BRAND_AND_PRODUCT_EXPERIENCE.md`، ولا تستبدلها أو تكررها. تشمل منظومة التصميم:

- ألوان العلامة الأساسية والمساندة، الألوان الدلالية لحالات النجاح والتحذير والخطأ والمعلومات.
- الخطوط العربية واللاتينية، المقاسات والأوزان وارتفاع السطر والتدرج الطباعي.
- الشعار واستخداماته وأحجامه ومساحاته الآمنة وأيقونات التطبيقات.
- الخلفيات العامة والخلفيات الخاصة بكل مجال؛ مع الحفاظ على الاستثناءات المعتمدة للمحادثات والغرف العامة والخاصة والمستأجرة.
- البطاقات والأزرار والحقول والقوائم والحوارات والنوافذ المنبثقة والتبويبات وأشرطة التنقل.
- الأيقونات والرسوم التوضيحية والحركة والانتقالات والاهتزازات عند دعمها.
- الحالات الفارغة والتحميل والنجاح والفشل وانقطاع الاتصال وانتهاء الجلسة وعدم الصلاحية.
- الوضع الفاتح/الداكن والثيمات والتخصيص ضمن الحدود المعتمدة.
- التباين، تكبير النص، قارئات الشاشة، التنقل بلوحة المفاتيح، التركيز المرئي وتقليل الحركة.

لا تعتمد صورة خلفية أو زخرفة على حساب وضوح النص أو قابلية استخدام الأزرار أو الأداء أو استهلاك البيانات. يجب تجهيز قصاصات وأحجام مناسبة للهاتف واللوحي والحاسوب مع بدائل منخفضة البيانات.

## 6. مواصفات كل شاشة وعنصر تفاعلي

يجب أن تمتلك كل شاشة معرفاً ثابتاً، ولكل زر أو عنصر تفاعلي معرفاً فرعياً ثابتاً. يتضمن سجل الشاشة على الأقل:

- المعرف والاسم العربي والإنجليزي والمجال والمالك الوظيفي.
- الهدف من الشاشة، المستخدمون والأدوار المسموح بها، ومتطلبات الدخول.
- المنصات والأحجام والاتجاهات المدعومة، وقواعد التكيف.
- مخطط الشاشة أو الصورة المرجعية وإصدار التصميم وتاريخ اعتماده.
- الأقسام والمكونات وحالات العرض والتحميل والفراغ والخطأ.
- مسارات التنقل إلى الشاشة ومنها، وروابط الرجوع والإغلاق.
- النصوص والترجمة وإمكانية الوصول.
- الملفات البرمجية المرشحة/المثبتة، الخدمات والنماذج وواجهات API/Callable وقواعد البيانات.
- الاختبارات المرتبطة ونتائجها وSHA الذي اختُبرت عليه.
- الحالة: موصوفة، مصممة، معتمدة بصرياً، مرتبطة برمجياً، منفذة، مختبرة آلياً، مختبرة على جهاز، مقبولة.

ويجب أن يتضمن سجل كل زر أو إجراء:

1. المعرف والاسم والنص والأيقونة ومكان الظهور.
2. الدور والصلاحية وشروط الإتاحة؛ مع تحقق خادمي للعمليات الحساسة.
3. الحدث عند الضغط أو النقر أو اللمس أو لوحة المفاتيح.
4. النتيجة والوجهة أو الحوار أو الإجراء الخلفي.
5. حالة الانتظار والنجاح والفشل وإعادة المحاولة ومنع التكرار.
6. الخدمة/Callable/المسار/النموذج/البيانات المرتبطة.
7. ضوابط الأمان والخصوصية والتدقيق.
8. الاختبار الذي يثبت السلوك على المنصات المستهدفة.

وجود زر في صورة أو ملف واجهة لا يثبت أن وظيفته تعمل. وإخفاء الزر لا يعد حماية أمنية؛ يجب فرض الصلاحية في الخادم.

## 7. الربط مع الأعمال والملفات السابقة

قبل تعديل أي شاشة أو خدمة، تنفذ مراجعة قراءة للمصدر على فرع التطوير، وتُنشأ خريطة ربط بين معرف الشاشة والعنصر وبين الملفات والوظائف الموجودة.

يجب تتبع الطبقات بحسب ما ينطبق:

- Flutter screens/widgets/routes وطبقة الحالة.
- خدمات العميل والمستودعات والنماذج والتحقق.
- Firebase Authentication وFirestore وStorage وCloud Functions.
- قواعد Firestore/Storage والصلاحيات ومطالبات الأدوار.
- خدمات الويب وPWA وManifest وService Worker.
- إعدادات Android وiOS وWindows وLinux وأدوات البناء والتوزيع.
- الاختبارات والوحدات والتكامل ولقطات الأدلة والوثائق.

لكل ربط تسجل الأدلة والمسارات وSHA والوظائف التي تم فحصها. لا تفترض علاقة ملف بشاشة من الاسم وحده؛ يجب التحقق من الاستدعاء والتنقل والاعتماد الفعلي.

### حالات الربط

| الحالة | المعنى |
|---|---|
| موجود ومثبت | عُثر على التنفيذ والعلاقة وأمكن إثباتهما من المصدر أو الاختبار المناسب |
| موجود جزئياً | بعض عناصر الشاشة أو دورة الوظيفة موجودة، لكن أجزاء أخرى ناقصة |
| واجهة بلا ربط مثبت | يوجد عنصر عرض، ولم يثبت وصوله إلى الوظيفة المقصودة |
| خدمة بلا واجهة مثبتة | توجد خدمة أو وظيفة خلفية، ولم يثبت استهلاكها من شاشة فعلية |
| متعارض/مكرر | توجد تطبيقات أو نماذج أو خدمات متداخلة تحتاج مصالحة قبل التعديل |
| غير متحقق | الأدلة غير كافية أو لم تكتمل المراجعة |

لا يجوز وصف أي ملف أو خدمة بأنها يتيمة أو زائدة قبل مراجعة الاستخدامات والاستدعاءات والاختبارات والتكاملات.

## 8. حماية الأعمال السابقة وإدارة التغيير

- التصميم الجديد لا يجيز حذف أو استبدال أو إعادة تسمية ملف أو خدمة موجودة تلقائياً.
- تُوثق العلاقة بين التصميم الجديد والواجهة الحالية والوظائف الخلفية قبل التعديل.
- إذا كان التنفيذ الحالي صحيحاً، يعاد استخدامه وربطه؛ وإذا كان جزئياً، يستكمل بأقل تغيير آمن؛ وإذا كان متعارضاً، يعرض تقرير المصالحة والخيارات على المالك.
- تُحفظ المراجع التاريخية والقرارات والنسخ السابقة وفق سياسة التوثيق؛ لا تعديل صامت ولا ادعاء أن المقترح القديم كان معتمداً.
- أي تغيير في سياسة أو صلاحية أو اقتصاد أو احتفاظ أو إجراء إنتاجي يتطلب مسار القرار والموافقة المنفصل المناسب.
- كل دفعة تنفيذية توثق وصف المهمة، المتطلبات، الملفات، السبب الجذري، التغييرات، الاختبارات، SHA، النتائج، العوائق، وحالة اعتماد المالك.

## 9. مسار العمل والاعتماد

يُنفذ العمل بالتسلسل التالي، مع إمكان تجميع الأعمال المترابطة في دفعات منضبطة:

1. حصر خريطة الأدوار والمنصات والشاشات والرحلات.
2. مراجعة وثيقة الهوية الحالية والمواصفات والقرارات لتحديد ما هو معتمد وما هو اقتراح وما هو معلق.
3. إعداد نظام التصميم ومكتبة المكونات والخلفيات وقواعد التكيف.
4. تصميم كل شاشة كاملة مع حالات الاستخدام والأزرار والتنقل والصلاحيات.
5. مراجعة المالك وإجراء التعديلات؛ لا ينتقل التصميم إلى حالة «معتمد بصرياً» إلا بموافقته.
6. فحص الملفات والوظائف السابقة وربط كل عنصر مرئي بالتنفيذ الموجود أو الفجوة المثبتة.
7. إعداد تقرير أثر وتغيير قبل البرمجة؛ لا استبدال عشوائياً.
8. تنفيذ التعديلات المعتمدة بأقل تغيير آمن، وإضافة الاختبارات المناسبة.
9. اختبار المنصات المتأثرة على SHA ثابت، ثم اختبار الأجهزة الفعلية عند الحاجة.
10. تحديث خريطة الواجهات وسجل القرارات والتوثيق المركزي بنتائج التنفيذ والاختبارات.

## 10. مصفوفة المنصات والقبول

| Web | متصفحات مدعومة، هاتف/لوحي/شاشة عريضة، RTL/LTR، لوحة مفاتيح وفأرة ولمس |
| PWA | قابلية التثبيت حسب المتصفح، manifest، الأيقونة، بدء التشغيل، التحديث، التخزين الآمن، الإشعارات/العمل دون اتصال حيث تدعم |
| Android APK | هاتف ولوحي، أحجام وكثافات مختلفة، أذونات، روابط عميقة، بناء وتوقيع وتثبيت |
| iOS/iPadOS | iPhone وiPad، أحجام واتجاهات مختلفة، أذونات، توقيع وبناء وفق إعدادات الهوية الحالية |
| Windows Desktop | نوافذ قابلة لتغيير الحجم، لوحة مفاتيح وفأرة، اختصارات، حزم تثبيت وتحديث |
| Linux Desktop | توزيعات/حزم مستهدفة محددة، توافق الإضافات، لوحة مفاتيح وفأرة، حزم تثبيت وتحديث |
| macOS Desktop (إن كان ضمن هدف الإصدار) | توافق Flutter والإضافات، التوقيع والتوثيق والبناء على بنية Apple |

معايير القبول لكل شاشة: دقة RTL/LTR، تكيف المقاسات، صحة التنقل، وضوح الحالات، الصلاحيات الخادمية، الأداء، الوصول، الترجمة، سلامة البيانات، وعدم تراجع الوظائف القائمة.

- **المعتمد:** إنشاء هذا القسم، وتغطية جميع الواجهات والمنصات، واعتماد خريطة مرئية/وظيفية موحدة، وربطها بالأعمال السابقة، والتمييز بين PWA المثبت من الموقع وتطبيق سطح المكتب المستقل، ووجود خيار تثبيت الموقع في القائمة العلوية عندما تكون قابلية التثبيت مدعومة.
