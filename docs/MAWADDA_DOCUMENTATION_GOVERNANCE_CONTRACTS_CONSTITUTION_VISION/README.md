## 1. وظيفة القسم

هذا هو المدخل المركزي لجميع وثائق Mawdda وسجلاتها وقراراتها ودساتيرها ورؤاها وعقودها وتقاريرها وأدلتها. يحفظ الروابط إلى المصادر الأصلية ولا يمحو تاريخها. كل وثيقة أصلية تبقى في مسارها الأصلي حالياً لتجنب كسر الروابط وسجلات Git والتاريخ؛ ويعد هذا القسم طبقة الفهرسة والحوكمة المركزية. لا يُعد النقل الفيزيائي للملفات مكتملاً، ولا تُحذف أو تُعاد تسمية المصادر ضمن هذه العملية.

## 2. ترتيب المرجعية

1. موافقة المالك الصريحة المحددة النطاق وأحدث تعديل معتمد منه.
2. دستور Mawdda المعتمد والقرارات اللاحقة الموثقة؛ مع بقاء النسخ الموحدة ذات حالة المسودة إلى أن تعتمد صراحة.
3. سجل القرارات المعتمدة والتتبع، مع مصدر الموافقة ومعرف القرار وحالته.
4. الرؤية الشاملة والميثاق ومواصفات المجالات والعقود والاتفاقيات.
5. سجلات التنفيذ والاختبارات وتقارير التدقيق وأدلة GitHub/Termux.
6. الاقتراحات والملاحظات والمحادثات: مصادر سياق لا ترفع نفسها إلى قرارات معتمدة.

عند التعارض: يسجل التعارض، وتوقف العملية المتأثرة، ويطلب حسم المالك إن لم يوجد قرار سابق واضح. لا تُستبدل وثيقة موقعة بمسودة، ولا يدمج اقتراح في سياسة نافذة.

## 5. سجل الحالة الموحد

يجب أن يحمل كل بند من الآن فصاعداً الحقول التالية في سجل القرارات أو سجل التتبع:
- معرف ثابت.
- عنوان ونطاق.
- النوع: قرار / دستور / رؤية / عقد / اقتراح / مهمة / تعديل / تقرير / اختبار / دليل.
- تاريخ الطلب، وتاريخ القرار، وتاريخ التنفيذ كلٌ على حدة.
- مصدر الطلب أو الموافقة ورابطه.
- الحالة: معتمد / مقترح / قيد التنفيذ / منفذ جزئياً / منفذ / مختبر / مقبول / مؤجل / مرفوض / محظور.
- الملفات والـcommits ذات الصلة.
- اختبارات مطلوبة ونتائجها الفعلية على SHA محدد.
- التعارضات والتبعيات والمخاطر.
- معيار القبول وقرار الإغلاق.

لا يجوز تحويل «موجود في الوثائق» إلى «منفذ»، أو «منفذ» إلى «مختبر»، أو «مختبر» إلى «مقبول» دون أدلة منفصلة.

## 6. ما يشمله سجل المصادر

سجل المصادر يدرج جميع ملفات `docs/` الظاهرة في شجرة الفرع وقت الحصر، بما فيها الوثائق المركزية والفرعية والتقارير والأدلة والـmanifests وسجلات Termux والاختبارات. التصنيف آلي أولي من أسماء الملفات والمسارات، ويجب تدقيقه يدوياً قبل أي دمج دلالي أو حذف أو اعتماد.

أما أعمال الكود والتغييرات التنفيذية فتظل في ملفات المشروع وسجل Git والـcommits، ويربطها سجل التنفيذ `IMPLEMENTATION_TRACEABILITY.md` بالمتطلبات والأدلة. لا يعني إدراج الوثائق هنا نقل جميع تغييرات الكود أو جميع commits أو كل البيانات المحلية غير المرفوعة.

## 7. قواعد الحفظ والتحديث

1. لا تحذف أو تستبدل النسخ التاريخية لمجرد وجود نسخة موحدة أحدث.
2. أضف ملحقاً مؤرخاً عند كل تحديث كبير، واحتفظ بتاريخ الإصدارات السابقة.
3. حدّث سجل المصادر والفهرس المركزي مع كل دفعة توثيقية.
4. افصل المقترحات عن القرارات، والاتفاقيات النموذجية عن العقود الموقعة.
5. لا تُنشئ التزاماً قانونياً أو موافقة نيابة عن المالك.
6. لا تغيّر `main` أو Firebase الإنتاجي أو موارد مدفوعة أو سياسات حذف حية ضمن أعمال الفهرسة.
7. لا تعتبر نجاح CI أو وجود ملف دليلاً على قبول المنتج النهائي.

## 8. فجوات معلنة لا يجوز إخفاؤها

- لا يثبت جرد GitHub ما لم يُرفع من Termux أو ما ورد في المحادثات ولم يوثق.
- المقارنة التاريخية بين الفروع لا تثبت وحدها أن كل التغييرات البرمجية الفريدة قد نُقلت.
- لا تثبت هذه المهمة نجاح اختبارات Flutter أو Functions أو Emulator أو محاكاة 5000 شخصية.
- المسودات الموحدة لا تصبح دستوراً نافذاً أو عقداً قانونياً بمجرد جمعها في هذا القسم.
- يلزم فحص كل وثيقة لتحديد النسخ المتعارضة، والتكرار، والقرار الأحدث، والاعتماد القانوني، وحالة التنفيذ.
