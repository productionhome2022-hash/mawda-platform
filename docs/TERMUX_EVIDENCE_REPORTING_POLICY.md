# سياسة قناة أدلة Termux ومتابعة التوحيد

**المعرّف:** GOV-MAWDDA-TERMUX-EVIDENCE-001  
**التاريخ:** 2026-11-21  
**الحالة:** معتمدة بتصريح المالك في المحادثة  
**المستودع:** `productionhome2022-hash/mawda-platform`  
**فرع التطوير الموحد:** `codex/mawda-full-platform-implementation`  
**مسار الأدلة:** `docs/audit/termux/`

## 1. القرار التنفيذي

اعتمد المالك أن تكون `docs/audit/termux/` قناة التقارير والأدلة الدائمة لجميع أعمال Termux المتعلقة بهذا المشروع، ابتداءً من تدقيق الفروع والتوحيد، وتُستخدم في الأعمال اللاحقة ذات الصلة متى طُلب من Termux تنفيذ عمل وإرسال تقرير.

يجب أن يرفع Termux مخرجاته مباشرة إلى هذا المسار في فرع التطوير الموحد، حتى يتمكن المساعد من مراجعتها عبر GitHub دون مطالبة المالك بنسخ سجلات Termux ولصقها في المحادثة.

## 2. قواعد الكتابة والحفظ

1. لا يُحذف أو يُستبدل أي ملف موجود في المستودع أو أي دليل سابق.
2. كل تشغيل ينشئ مجلداً جديداً باسم زمني فريد تحت `docs/audit/termux/runs/<UTC timestamp>-<short-id>/`.
3. تُكتب التقارير بصيغ نصية قابلة للمراجعة مثل Markdown وJSON وCSV وTXT، مع فهرس `README.md` في مجلد التشغيل.
4. يرفع Termux ملفات الأدلة إلى فرع التطوير الموحد فقط، ولا يرفعها إلى `main` أو أي فرع إنتاجي.
5. لا تُضمّن الأسرار أو مفاتيح التوقيع أو ملفات الاعتماد أو رموز الوصول أو بيانات الأعضاء الخاصة أو سجلات تحتويها. يجب إجراء فحص أسرار محلي قبل الرفع، وحجب أي ملف مشتبه به مع تسجيل مساره وسبب حجبه دون طباعة قيمته.
6. إذا فشل فحص الأسرار أو تعذر التأكد من سلامة المخرجات، لا ترفع المحتوى المشتبه به؛ ارفع تقريراً آمناً يوضح الملفات المحجوبة والسبب.
7. لا يكتب Termux فوق تقارير تشغيل سابق ولا يعيد استخدام مجلد سابق.
8. يجب تسجيل SHA المصدر وSHA الفرع المستهدف ووقت التنفيذ وإصدار Git وأوامر الفحص والنتائج ورموز الخروج.

## 3. نطاق التقارير المطلوبة في أعمال التوحيد

بحسب المرحلة وإمكانات البيئة، تشمل الأدلة:

- قائمة الفروع البعيدة كاملة مع SHA لكل فرع.
- قائمة PRs وحالتها وbase/head SHA وDraft والحالة والملفات المتغيرة.
- علاقات commits وmerge-base وahead/behind.
- جرد الملفات المتغيرة، مع حالات الإضافة والتعديل والحذف وإعادة التسمية والملفات الثنائية.
- مقارنة التغييرات مع الفرع الموحد، وتحديد ما هو موجود مسبقاً وما هو فريد.
- ملفات patch/diff للمراجعة بعد فحص الأسرار وتنقيح أي محتوى حساس.
- جرد الاعتماديات والتبعيات والملفات المرتبطة التي تحتاج مراجعة.
- نتائج فحوصات الأسرار والملفات الكبيرة والثنائية والمحتوى المولد.
- سجل العيوب والثغرات والفجوات والتعارضات ومخاطر الدمج، مع عدم ادعاء اكتشاف شامل يتجاوز الأدوات المستخدمة.
- سجل النقل والدمج اللاحق: المصدر، الملفات/التغييرات، القرار، commit، والنتيجة.
- سجل التحقق النهائي والاختبارات التي شُغلت فعلياً، مع SHA والنتائج.

## 4. سير العمل والحدود

1. يبدأ Termux بجرد قراءة فقط وجمع الأدلة. لا ينفذ دمجاً آلياً شاملاً أو cherry-pick جماعياً أو force-push.
2. يرفع الأدلة الآمنة إلى مجلد تشغيل جديد في فرع التطوير الموحد.
3. يراجع المساعد التقارير والملفات التي أصبحت متاحة في GitHub، ثم يحدد التغييرات المقبولة والمكررة والمتعارضة والمحجوبة.
4. تتم عمليات نقل الكود على دفعات مفهومة ومراجعة، مع تقارير أدلة جديدة في المسار نفسه. لا يُسمح بالاستبدال أو الحذف الصامت.
5. يظل حذف الملفات أو الفروع أو النسخ القديمة ممنوعاً حتى اجتياز بوابة التوحيد ومراجعة المالك وإصدار موافقة مستقلة على التنظيف.
6. لا يُجرى دمج إلى `main` أو نشر أو تعديل إنتاج أو Firebase إنتاجي أو تفعيل فوترة/موارد مدفوعة.
7. تبقى الاختبارات الخارجية ومحاكاة 5000 شخصية مؤجلة إلى ما بعد اكتمال توحيد الفروع، وفق توجيه المالك السابق.
8. لا يرسل Termux تقريراً مرحلياً يدوياً للمالك؛ تُرفع الأدلة إلى GitHub. ويُعد تقرير ختامي عند اكتمال النطاق.

## 5. التزامات المساعد

- مراجعة مجلد `docs/audit/termux/` مباشرة بعد رفع الأدلة، وعدم افتراض أن مجرد نجاح push يعني أن التقرير قُرئ أو أن المهمة اكتملت.
- فحص تقارير التشغيل الجديدة ومقارنة SHA ومحتوياتها مع حالة GitHub.
- عدم إعلان اكتمال أي مرحلة قبل تحقق الأدلة.
- عدم مطالبة المالك بنسخ مخرجات Termux يدوياً إذا كانت قد رُفعت بنجاح وأصبحت قابلة للقراءة.
- عند كل أمر لاحق يطلب من Termux تنفيذه، تضمين إلزام صريح برفع التقرير والأدلة الآمنة إلى هذا المسار على فرع التطوير الموحد.
- إذا تعذر الرفع، يوقف Termux أي خطوة لاحقة تعتمد على وصول التقرير، ويسجل سبب الفشل محلياً دون حذف الأدلة.

## 6. بوابة اعتماد التشغيل

يُعد التشغيل قد سلّم أدلته فقط بعد:
- نجاح إنشاء مجلد تشغيل جديد وفريد.
- نجاح فحص الأسرار أو حجب الملفات المشتبه بها.
- نجاح commit وpush إلى فرع التطوير الموحد دون force.
- التحقق بعد الرفع من وجود الملفات على GitHub.
- تسجيل SHA commit الرابط والمسار وعدد الملفات وحالة الرفع.

**هذه السياسة تنظّم قناة الأدلة والتقارير؛ ولا تمنح Termux صلاحية حذف الملفات أو الدمج العشوائي أو تعديل الإنتاج أو تجاوز موافقات المالك.**
