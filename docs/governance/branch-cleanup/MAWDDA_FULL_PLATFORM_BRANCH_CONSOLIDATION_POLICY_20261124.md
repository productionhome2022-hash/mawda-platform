# سياسة توحيد الأفرع الخارجية في جسم Mawdda Full Platform

- **الحالة:** سياسة تنفيذية معتمدة بتوجيه مالك المشروع.
- **تاريخ الاعتماد:** 2026-11-24.
- **المستودع:** `productionhome2022-hash/mawda-platform`.
- **الجسم المستهدف الوحيد:** `codex/mawda-full-platform-implementation`.
- **النطاق:** جميع الأفرع الأخرى في المستودع، بما فيها أفرع الاسترداد والحوكمة والميزات والتجارب والإصلاحات والاختبارات والوثائق.

## 1. الغاية والقاعدة الحاكمة

يكون فرع `codex/mawda-full-platform-implementation` جسم المنصة الوحيد الذي تُستوعب فيه الأعمال المطلوبة. لا يُنشأ جسم بديل أو فرع أساسي موازٍ. يجب نقل الوثائق والحوكمة والسجلات والفهارس ذات القيمة إلى داخل شجرة هذا الفرع، وعدم إبقائها موزعة في أفرع مرشحة للحذف.

## 2. الجرد والمطابقة الإلزاميان

يُفحص كل فرع خارج الجسم المستهدف فحصاً مستقلاً، ويشمل ذلك:
- رؤوس الفروع وSHA وتسلسل الالتزامات وتواريخها وعلاقات السلف.
- الالتزامات الفريدة والمكررة، مع استخدام SHA وpatch-id عند توفره وعدم اعتبار تطابق أسماء الملفات دليلاً على تطابق المحتوى.
- فروق الملفات الفعلية ومحتويات الأشجار، بما في ذلك التغييرات اللاحقة التي ربما أعادت تنفيذ سلوك سابق.
- الميزات والإصلاحات والتحسينات المعمارية والأمنية.
- الاختبارات ووحدات الاختبار واختبارات التكامل والتغطية المتاحة.
- وثائق المنتج والحوكمة والقرارات والسجلات والفهارس وخطط التنفيذ.
- التبعيات والتعارضات والآثار الجانبية والتوافق مع الدستور والقرارات المعتمدة.

## 3. التصنيف الإلزامي لكل فرع ولكل مجموعة تغييرات

يُسجل كل عنصر في سجل المطابقة بإحدى الحالات:
1. مستوعب بالفعل في الجسم المستهدف.
2. فريد ومطلوب — ينقل كاملاً بعد المراجعة.
3. مستوعب جزئياً — يستكمل الجزء الناقص فقط.
4. تحسين متقدم — يراجع توافقه ثم ينقل إذا ثبتت سلامته وقيمته.
5. مكرر أو غير مطلوب — لا ينقل، ويُدرج الفرع في قائمة مرشحي الحذف بعد اكتمال الفحص.
6. غير محسوم/متعذر التحقق — يبقى محفوظاً ولا يوصى بحذفه.

يجب تسجيل SHA المصدر، ومرجع/مسار التغيير، وقرار النقل أو عدمه، وSHA الناتج أو موضع الاستيعاب، ودليل التحقق، وأي تحفظات.

## 4. قواعد النقل والدمج

- يكون الاستيعاب داخل فرع الجسم المستهدف نفسه فقط.
- تُفضل عمليات النقل الانتقائي الواضحة والقابلة للمراجعة، مع حفظ نسب المصدر وسجل SHA متى أمكن.
- لا يُنقل تغيير مكرر أو متعارض قبل تحليل السلوك النهائي.
- لا تُستبدل ملفات كاملة لمجرد أن نسخة فرع آخر أحدث؛ يجب فحص الفروق والسياق.
- لا تُحذف أو تُهمل وثيقة أو سجل أو اختبار فريد قبل حفظه واستيعابه أو توثيق سبب عدم الحاجة إليه.
- بعد كل دفعة نقل، تُراجع الفروق ويُتحقق من عدم فقدان تغييرات أو إدخال تكرار أو إضعاف الأمان.

## 5. سياسة الاختبارات — GitHub الداخلي فقط

بناءً على توجيه المالك لهذه المهمة، يقتصر التحقق الاختباري المطلوب على الاختبارات والفحوصات التي توفرها بيئة GitHub الداخلية للمستودع، مثل GitHub Actions والـ workflows والـ jobs والفحوصات الآلية المتاحة فعلياً.

- لا تُشغّل محاكاة 5,000 شخصية ضمن هذا المسار.
- لا يُطلب ولا يُشترط اختبار خارج بيئة GitHub الداخلية.
- لا يُطلب ولا يُشترط اختبار على جهاز فعلي أو قبول يدوي على أجهزة.
- لا يُطلب ولا يُشترط اختبار خارجي غير متاح ضمن بيئة GitHub الداخلية.
- لا يُعد غياب هذه الاختبارات الخارجية عائقاً أمام إغلاق مهمة المطابقة والنقل ضمن هذا النطاق.
- تُشغّل الاختبارات الداخلية المتاحة والملائمة للتغييرات فقط، ويُوثق اسم workflow/job والـ commit SHA والحالة والنتيجة.
- يجب التمييز بوضوح بين: ناجح، فاشل، ملغى، لم يُشغّل، وغير متاح. لا يُعلن نجاح اختبار لم يُشغّل.
- لا تعني هذه السياسة اعتماد المنصة للإطلاق أو الإنتاج، ولا تلغي بوابات السلامة والإطلاق المنفصلة عند اتخاذ قرار إطلاق لاحق.

## 6. قائمة الحذف وحظر الحذف المبكر

لا يُحذف أي فرع أثناء الجرد أو المطابقة أو النقل. بعد فحص الفرع بالكامل ونقل كل ما يستحق واستيعابه والتحقق منه، يُصنف:
- **مرشح للحذف:** ثبت عدم احتوائه على عمل مطلوب غير محفوظ.
- **محفوظ مؤقتاً:** توجد تغييرات غير محسومة أو تعذر التحقق منها.
- **ممنوع الحذف حالياً:** توجد أعمال فريدة لم تُنقل أو لم يتم التحقق من استيعابها.

تتضمن قائمة الحذف النهائية اسم الفرع وSHA رأسه وآخر التزام ذي صلة وملخص ما احتواه ودليل حفظ الأعمال وسبب عدم الحاجة إليه. إعداد القائمة لا يعني تنفيذ الحذف. حذف الفروع عملية مستقلة تتطلب موافقة صريحة مستقلة من المالك بعد عرض القائمة النهائية.

## 7. حدود الصلاحيات

هذه السياسة لا تمنح إذناً بدمج `main` أو النشر أو تعديل الإنتاج أو موارد Firebase أو تفعيل الفوترة والخدمات المدفوعة أو حذف بيانات/موارد إنتاجية. لا تُحذف فروع Git دون موافقة صريحة مستقلة. يبقى العمل ضمن فرع التطوير المستهدف.

## 8. معايير إغلاق المهمة

لا تُغلق المهمة إلا بعد:
1. حصر جميع الفروع الخارجية المتاحة ومراجعة صفحات النتائج حتى اكتمال القائمة.
2. إتمام المطابقة على مستوى الالتزامات والفروق والملفات والميزات والاختبارات والوثائق.
3. نقل الأعمال الفريدة والمطلوبة إلى الجسم المستهدف.
4. حفظ الوثائق والحوكمة والسجلات والفهارس المطلوبة داخل شجرة الجسم المستهدف.
5. تشغيل الاختبارات الداخلية المتاحة والملائمة وتوثيق نتائجها دون ادعاء نتائج غير منفذة.
6. إنشاء سجل نهائي للفروع المصنفة للحذف أو للحفظ المؤقت مع SHA والأسباب.
7. عدم تنفيذ أي حذف قبل موافقة المالك المستقلة.

## 9. سجل التنفيذ

تُضاف هنا سجلات التنفيذ المتتابعة: الفروع المفحوصة، SHA المرجعية، نتائج المقارنة، عناصر النقل، الالتزامات الناتجة، الاختبارات الداخلية، والعوائق. لا يُعد هذا المستند وحده دليلاً على إتمام أي نقل أو اختبار؛ يجب أن يرتبط كل ادعاء بدليل GitHub فعلي.
